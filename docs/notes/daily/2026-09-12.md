## Blocked / surprises

- The checkout came from another machine: the venv had to be rebuilt on Python 3.12 and a
  JDK installed for Spark — `jdk4py` from PyPI, since the proxy blocks the usual
  downloads. `JAVA_HOME` has to point at `jdk4py/java-runtime`.
- GitHub is blocked by the proxy, so there is no Hadoop `winutils.exe`/`hadoop.dll` here
  and Spark cannot touch the local filesystem: `spark.read.json(<local path>)` and parquet
  writes die in `NativeIO$Windows.access0`. The Spark tests therefore build their bronze
  DataFrames from JSON lines held in memory and never write parquet locally.
- Every PySpark task that runs Python code died here with "Python worker exited
  unexpectedly (crashed)". The worker is fine: PySpark 3.5 on Windows runs
  `python -m pyspark.worker` (no `fork`, so no daemon), and that path never flushes the
  64 KiB buffer of its result socket — it leans on the interpreter's exit-time flush,
  which on this box happens too late for the JVM to read. `tests/conftest.py` puts a
  `sitecustomize` on the worker's PYTHONPATH that flushes at `atexit`; with it, every
  Spark test passes. Linux uses `pyspark.daemon`, which flushes explicitly, so the
  cluster is unaffected.
